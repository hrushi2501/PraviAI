# Functionality audit — government fixed-asset manager

Audit date: 28 September 2026. This is a source inspection of the working tree, including the existing uncommitted implementation. It does not claim live deployment, database installation, vendor delivery, or browser acceptance. UI/auth refinements and server hardening undertaken alongside this audit require their own validation; the findings below record the inspected baseline.

## Conclusion

The schema and typed backend cover substantial domain ground. The inspected baseline mixed synthetic operational screens and SQL dashboard reads; the latest changes replace production `/app` screens with actual scoped database reads and selected persisted mutations. The full described operational journey is still incomplete. A working SQL contract, a server action, and a complete independently reviewed application journey are separate completion levels. The matrix below preserves baseline findings; the resolution logs at the end describe current changes.

Severity: **P0** security or misleading trusted conclusions; **P1** required journey blocked; **P2** required usability/coverage incomplete; **P3** explicitly deferred. Status: **SQL** contract exists; **backend partial** action/service exists but integration or contract remains incomplete; **preview** synthetic client workflow; **missing** no application operation found. SQL existence is not execution evidence.

## Current remaining release blockers

The baseline matrix below is reconciled by the resolution logs at the end. The current blockers are the complete inspection/complaint/restoration creation-to-reinspection journey, protected evidence, real invitation delivery and governance, sensitive lifecycle approvals, stable retry keys, full reporting drill-down/exports and seven-language coverage. Production pages now use actual scoped records; registration draft/correction/review and inspection/work review decisions are wired. Hosted multi-user acceptance remains unverified.

Additional schema review finding: authority/department memberships have `expires_at` columns, but `authority_admin`, `authority_read` and `department_permission` do not check expiry. No implemented app operation sets temporary grants, so temporary-access behavior must be defined and tested before exposing it. An expired non-null timestamp alone currently does not revoke an active membership; `active=false` is the available enforced revocation path.
